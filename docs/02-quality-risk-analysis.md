# 02. 品質リスク分析

| Risk ID | 機能 | 品質リスク |影響度|発生可能性|優先度|主なテスト|選定理由|
|---|---|---|---:|---:|---|---|---|
| R-01 | ログイン | 正常な利用者がログインできない | 3 | 2 | 最優先 | API + UI | 入力パターンはAPIで広く検証し、主要なログイン導線はUIで保証する。 |
| R-02 | 認証・権限 | 権限外のデータ・操作へアクセスできる | 3 | 2 | 最優先 | API中心 + UI補完 | 権限条件をAPIで効率よく検証し、代表的な画面操作をUIで確認する。 |
| R-03 | 商品・カート | 商品・数量などの状態が正しく保持されない | 3 | 2 | 高 | API + E2E | 状態と組合せはAPI、ユーザー視点の主要導線はE2Eで確認する。 |
| R-04 | 購入 | 注文結果と画面表示が不整合になる | 3 | 1 | 高 | API + E2E | ビジネス上重要なため、サービス層とユーザー導線の両方を確認する。 |
| R-05 | 画面表示 | 表示・操作性の問題で利用しづらい | 2 | 2 | 中 | UI + A11y + 手動 | 機械判定できる部分は自動化し、UX等の人の判断が必要な部分は手動で残す。 |
| R-06 | 性能 | 負荷上昇時に応答遅延やエラーが増加する | 3 | 2 | 高 | JMeter | 機能テストでは検出しづらい非機能リスクのため性能テストで確認する。 |

優先度は影響度と発生可能性から判断する。実装済み範囲と未実装範囲は[05-test-coverage-map.md](05-test-coverage-map.md)で管理する。
