# 07. 品質指標

## 主な指標

| 指標 | 意味 | 確認方法 |
|---|---|---|
| PASS率 | 実行テストの成功割合 | pytest / Newman / JMeter結果 |
| 失敗件数 | 修正・調査が必要なテスト数 | CIジョブ・JUnit/レポート |
| 不安定テスト率 | 同じ変更でPASS/FAILが変動する割合 | CI履歴を将来集計 |
| 主要導線カバレッジ | ログイン、カート、購入が回帰対象になっているか | カバレッジマップ |
| APIリスクカバレッジ | 正常・異常・境界・認証/認可を確認できる範囲 | Postmanコレクション |
| 応答時間・エラー率 | 性能劣化の兆候 | JMeter統計JSON・HTMLレポート |

## 失敗テストの扱い

1. まず失敗の再現性を確認する。
2. 製品不具合、テスト不具合、環境不具合、外部依存不具合に分類する。
3. 製品不具合は根本原因と影響範囲を記録する。
4. テスト不具合はLocator、待機、テストデータ、並列性を確認する。
5. 不安定テストは無条件に再実行せず、再現条件と改善期限を記録する。

## 性能改善サイクル

1. JMeterを実行し`results.jtl`を取得する。
2. `scripts/analyze_jmeter.py`でBefore指標を確認する。
3. ボトルネック候補をログ、メトリクス、トレースで観測する。
4. 原因仮説を立ててサービスまたはテスト環境を改善する。
5. 同じ負荷条件で再実行し、After指標を比較する。

現時点ではAPMやクラウド可観測性基盤が未導入であるため、Before/AfterはローカルJMeter結果を基準に記録する。
